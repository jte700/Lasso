# Lasso: working notes for Claude

Lasso indexes local folders and suggests source-backed text while the user types in any Mac app (Tab accepts). A local Node server (`src/`) does indexing, ranking and sharing; a native AppKit menu bar app (`desktop/`) draws the suggestion card, Source Inspector, share composer and The Ranch. No language model is involved in suggestions. A model writes only when the person hands a backslash prompt to an AI writer they chose (see AI writers below), and then it is sent that prompt and what it looks up through Lasso.

Read only what a task needs. Files are split by feature and mostly under 500 lines; find the right one in the table below or with `grep -rn`, then read line ranges.

## Build and test

```bash
npm test                         # all Node tests (about 1 minute); one file: node --test test/<name>.test.js
npm run cli -- <command>         # the lasso CLI from the checkout (bare: the interactive shell); `npm link` puts `lasso` on PATH
npm run desktop:test             # native unit checks (a subset of desktop/ files, listed in package.json)
npm run desktop                  # builds dist/Lasso.app; the user's app only changes after this and a relaunch
npm run release:mac              # the downloadable Lasso.dmg (Intel + Apple silicon) in dist/release; see docs/releasing.md
```

- New Swift files in `desktop/` are compiled into the app on their own (`build.sh` takes every `desktop/*.swift` but `LassoLauncher.swift`). Add one to the `desktop:test` script in `package.json` if it is testable without AppKit windows. Frameworks are linked in `build.sh` only.
- Releases: pushing a `v*` tag runs `.github/workflows/release.yml`, which builds, signs and publishes `Lasso.dmg`, `Lasso-Setup.exe` and `Lasso-Setup-arm64.exe`; the site links to `releases/latest/download/<file>`. Nothing there needs editing per merge. Setup and secrets: `docs/releasing.md`.
- The website at mylasso.ca is `website/`: static pages, with the waitlist and share-link functions in `website/api/`. Vercel (project lasso-website) deploys it from `main`. The site before the 2026-11-21 redesign is kept in `website-previous/`, not served. Card pictures and clips in `website/assets/media` are drawn from `website/media-src` (see `website/README.txt`).
- `npm test` has a known flaky race (`UNIQUE constraint failed: object_index_bases.snapshot_id` in `test/connections.test.js`); rerun the file alone before treating it as a regression.
- Native UI checks without launching the app: compile the `build.sh` sources minus `Lasso.swift` with `-D BROWSER_GEOMETRY_TEST` plus a scratch `main.swift` that calls a `runRegression`/`regression*` function (`GlobalAssistant.regressionSuggestionNavigation`, `AssistSlidePreviewView.runRegression`, `PassageSlidesBody.runRegression` (swipes between slides), `PreviewWordMarks.runRegression`, `ShareComposerView.run*Regression`; test-only code lives in `*+Regressions.swift`). Copy `desktop/BuildConfig.swift` to the scratchpad first: `npm run desktop` rewrites it mid-build. The first run after a build can fail timing checks; run twice before calling it a regression. Put the source list in a script file: an inline zsh `${(f)...}` array trips the shell safety check.
- To see The Ranch without touching the user's library: start a server on scratch data (`PORT=4791 LASSO_DATA_DIR=<scratch> node --disable-warning=ExperimentalWarning src/server.js`), add folders with `POST /api/workspace/directories`, then from a scratch `main.swift` (same source list as above) make `RanchWindowController(actions:)`, call `show(serverURL:)`, set `store.stage` to step through the opening, and picture the window with `screencapture -x -o -l <windowNumber>`.
- To check suggestions against real files without touching the user's library: `createApplication({ dataDir: <scratch>, watchProjects: false })`, `workspace.add([...folders])`, `workspace.predict({ text, cursor })`. Test folders live in `~/Desktop/Software Tests/`.
- Relaunching: quit Lasso and `LassoLauncher` by pid, then `open dist/Lasso.app`. Several copies can run at once; check which bundle is running before keystroke tests.

## Conventions

- Comments and test names are plain sentences about behaviour ("A slide's title completes"), matching the surrounding density. No em dashes in prose written for the user.
- Tests: `node:test` + `assert/strict`, Arrange/Act/Assert, real temporary folders through `createApplication`. Write the failing test first.
- Server responses keep their existing shape; add fields, never rename them, since the Mac app and the Windows app (`desktop-windows/`) both read them.
- Commits: `type: description` (feat, fix, refactor, test, docs, chore), merged into `main` with `--no-ff` from `claude/*` branches. Commit only when asked.

## Keeping it cheap to change

- New code goes in the feature file it belongs to, or a new file of its own; split a file before it passes about 800 lines. Swift extensions in other files need members widened from `private` to internal.
- Still large, read by range: `src/dependencies/step-model.js` (1,476), `document-extraction.js` (1,307), `src/terminal/graph.js` (1,425), `desktop/Lasso.swift` (1,550), `desktop/DirectoryMenu.swift` (1,069), `public/terminal.css`, and the test files `desktop/tests/main.swift` and `test/*.test.js`.
